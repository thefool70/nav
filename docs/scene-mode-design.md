# 场景模式：物体模式的前后处理

状态：已按共识接入代码，尚未运行验收。完整现行流程见 `algorithm.md` 的“两种搜索模式”。

## 核心原则

场景模式是物体模式的“装饰器”版本：前处理生成关联物体清单，中间直接复用物体搜索流程，尾处理确认场景。这里描述流程关系，不要求引入 Python 装饰器、包装类或新的通用框架。

除已明确的前后处理外，其余行为默认继承物体模式，不逐项重新设计或请求确认。代码改动限于必要的数据贯通和前后处理接入，保持现有项目架构。

## 前处理

每轮任务开始时，由 Qwen 根据目标场景生成 3–5 种强相关、有区分度、便于视觉识别的物体类别，避免桌子、椅子等过于通用的类别。清单本轮固定。未生成有效清单时重试一次，仍失败则明确提示并结束任务。

## 复用物体模式

将清单作为可接受目标类别，直接复用现有图像采集、连续检测、感知队列、YOLOE/Qwen 判别融合、探索、定位、接近、停靠及失败恢复。评分沿用物体搜索的现有语义，以清单中的物体为搜索目标，不另加场景专用探索评分路径。

一种可靠的线索物体即可触发接近；不要求多类别共现或跨帧投票。中等置信度联合确认仍要求同帧、同类别且框重叠达到现有门槛。

定位保留 RGB-D 掩码、检测框深度和地图射线保底。射线保底沿目标视线寻找首个已知障碍，作为目标位置假设，再按现有地图约束规划停靠。全部历史线索仍无法定位时，沿用返回首条拍摄位姿并停止的现有行为，不另加场景专用保底。

现有检测接口只有一个固定类别，且结果未贯通类别身份；需将其最小扩展为类别清单及带类别的检测结果，供同一条物体流程使用。不为每个类别建立独立进程、队列或导航流程。

## 尾处理

截住物体模式停靠后的完成出口，原地旋转一圈，分方向停稳采图。按相机视场选择覆盖完整一圈的朝向，将画面按顺序组成带编号的网格图，通过现有单图接口交给 Qwen 综合判断。不做几何全景拼接。

只有确认机器人已经进入目标场景，才宣布场景搜索成功。没有物体线索时，不保留 Qwen 独立宣布场景成功的旧路径。

确认不是目标场景时，排除本次环视入镜的具体线索物体，其余先不处理；不扩展到整个区域或全局同类别物体。随后回到物体模式已有的下一条线索／继续探索流程。未达到确认门槛不能宣布成功；模型或设备异常沿用现有错误处理，不伪装成场景否决。

## 必要接入与边界

- 类别清单和类别身份贯通现有检测结果；保留环视物体的类别、框、图像位姿对应，优先复用现有定位来关联并排除具体线索，不引入通用实例跟踪。
- 复用现有原地转向动作与图像快照封装。现有探索扫描按 Frontier 选方向，不保证完整一圈，不能直接把其结束后转入探索的行为套入环视确认。
- 活动目标处理期间普通语义队列会暂停；尾处理的确认请求须在现有运行层直接衔接，避免排入暂停队列等待。
- 旧 scene 返回拍摄位姿即成功的出口由新流程替代；物体模式自身的成功语义保持不变。
- 日志与现有可视化记录清单、触发接近的物体、环视合图、场景判断和排除线索，便于检查整个过程。

领域术语见根目录 `CONTEXT.md`。具体字段、函数组织及参数适配由实现负责，不作为新的行为选择逐项询问。

未运行测试、模型请求、仿真或硬件验证。运行验收按仓库规则在用户授权范围内进行。

实例排除以同地图、同类别、0.5 m 内的位置关联为最小实现；环视中无法定位的检测单独记录，不能可靠跨画面排除。
