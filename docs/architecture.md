# 架构说明

项目围绕五项工作组织：连接环境、理解画面、决定行动、组织运行、记录过程。
各部分共用一套数据约定，使同一套导航算法能够运行在仿真和真机上。

## 各部分负责什么

以下目录位于 `src/robot_nav/`：

| 目录 | 职责 |
| --- | --- |
| `platforms/` 环境适配 | 从仿真器或真机获取图像、深度、位姿和地图，执行移动并反馈结果 |
| `perception/` 感知 | 分析画面，提供目标线索、目标位置和探索方向的语义评分 |
| `navigation/` 导航决策 | 决定观察哪里、往哪里探索、如何接近目标，以及失败后怎么办 |
| `pipeline/` 运行流程 | 读取配置、准备组件，串起感知、决策和执行，负责启动与退出 |
| `recording/` 过程记录 | 保存日志和可视化，帮助查看识别、路径与决策过程 |
| `interfaces/` 共享约定 | 统一各部分交换的数据含义，以及环境需要提供的能力 |

## 它们如何协作

```text
环境适配：提供图像、位姿和地图
        ↓
感知：提供目标线索与方向评分
        ↓
导航决策：选择观察、探索或接近目标
        ↓
环境适配：执行动作并反馈结果
        ↓
导航决策：根据实际结果继续或调整行动
```

运行流程负责连接这些步骤，过程记录伴随整个运行。感知可以在后台分析画面，
导航在当前动作完成后接收结果；没有语义评分时，仍可根据地图继续探索。

以“寻找椅子”为例：环境适配提供画面和地图，感知发现椅子并估计位置，
导航选择附近可达的停靠点，运行流程交给底盘执行。如果无法到达，导航决定换点或处理其他线索。

## 职责边界

导航决策保存“已经探索哪里、还有哪些分支、正在处理哪个目标”；
感知保存待分析画面和识别结果；环境适配管理设备状态、地图和正在执行的动作。
各部分负责自己的状态，日志和可视化不参与决策。

搜索策略集中在导航模块。模型调用留在感知模块，设备通信、底层规划与避障留在环境适配侧。
这样修改探索策略不需要了解底盘协议，接入新底盘也不需要复制导航算法。

## 启动、退出与环境切换

启动时读取配置，准备模型、记录工具和所选环境，再进入导航循环。
设备专属准备由适配层完成，例如 Hermes 的建图准备。退出时先停止底盘动作，再释放模型和其他资源。

Habitat 和 Hermes 共用运行、感知与导航流程，但传感器、地图和运动方式由各自环境提供，
实际轨迹不必相同。新底盘需要按 [底盘接口](chassis-interface.md) 提供相同含义的输入和执行反馈。

搜索规则见 [算法说明](algorithm.md)，启动方法见 [Hermes](hermes.md) 和 [Habitat](habitat.md)。
