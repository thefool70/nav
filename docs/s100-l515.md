# S100 + L515 真机 Adapter

该 Adapter 把 WHEELTEC S100 和 RealSense L515 转换为项目统一的
`ChassisInterface`。核心导航算法不包含任何 S100、串口或 RealSense 分支。

## 数据流

```text
S100 速度反馈 ──► 反馈里程计 ──► Pose2D ───────────┐
L515 RGB-D ─────► 深度占用图 ──► NavigationFrame ─┼─► core
core 相对位姿 ──► 已知自由区 A* ─► 差速分段执行 ───┘
```

S100 不能横移。Adapter 会把 `(forward, left, yaw)` 转换为转向、直行和最终转向。
平移路径最多执行 0.2 m 就停车，重新采集深度并规划下一段。

## 代码位置

| 文件 | 单一职责 |
| --- | --- |
| `adapter.py` | 组合设备数据、规划和运动，公开统一 Adapter |
| `s100_serial.py` | S100 的 11 字节命令和 24 字节反馈协议 |
| `l515_camera.py` | 采集对齐到 RGB 的米制深度图 |
| `mapping.py` | 把深度射线累计为未知/自由/障碍三态图 |
| `planner.py` | 在已知自由栅格中执行 A* |
| `motion.py` | 反馈里程计、预检、低速差速执行和停止确认 |

## 安装

设备已在 Windows 下验证，首次接真机建议使用原生 Windows Python 3.10 或
3.11。WSL 只有在串口和 L515 都已转发给 WSL 后才能使用，并需把 `COM3` 换成
实际的 `/dev/tty...` 路径。

```bash
micromamba create -n robot-nav-s100 python=3.11 pip
micromamba activate robot-nav-s100
python -m pip install -e ".[s100-l515,visualization]"
```

启动前实测 L515 光心相对底盘原点的位置：高度向上为正，前向和左向为正，
yaw 向左为正，pitch-down 朝地面为正。下面的 `0.60` 只是命令示例，不是设备
标定值。

## 启用方式

先让驱动轮完全离地，只运行预检。此模式只发送停止命令，并检查 S100 已使能、
反馈静止且 L515 能生成 RGB-D 和占用图：

```bash
python -m robot_nav s100-l515 --serial-port COM3 --camera-height-m 0.60 --preflight-only
```

预检通过后，可以用随机方向评分调试算法与真机链路。该命令会真实移动底盘，
但不会调用大模型，也不能识别语义目标：

```bash
python -m robot_nav s100-l515 --serial-port COM3 --camera-height-m 0.60 \
  --camera-forward-m 0.00 --camera-left-m 0.00 --camera-yaw-deg 0 \
  --camera-pitch-down-deg 0 --target "门口" --debug-random-score --enable-motion
```

上面的续行符适用于 Bash；PowerShell 中可写成单行，或把 `\` 换成反引号。

完整语义搜索需设置 `ROBOT_NAV_VLM_API_KEY`，然后去掉
`--debug-random-score`。`--enable-motion` 是真机导航的强制确认开关，省略时入口
会拒绝发送非零速度。Rerun 默认开启，用 `--no-rerun` 关闭。

## 当前边界

- 位姿仅由 S100 的线速度和角速度反馈积分，长距离运行会累计漂移。
- 占用图是固定 20 m × 20 m 的局部研究地图；未知区域不可规划，路径可能安全地
  拒绝而不是冒险穿越。
- pitch-down 会用于深度建图，但当前目标框定位仍按近似水平相机计算；做语义目标
  定位时应先保持相机接近水平，或后续扩展 core 的三维相机外参。
- Rerun 记录算法帧和每个分段停车后的新帧，不显示电机控制周期内的连续视频。
- 这不是动态障碍安全系统。首次运动必须轮子悬空，并保留独立停止看门狗或可立即
  断电的人；不要无人值守运行。
- 当前 Adapter 实现尚未完成真机验证。
