# S100 + L515 真机 Adapter

该 Adapter 把 WHEELTEC S100 和 RealSense L515 转换为统一的
`ChassisInterface`。导航算法只读取 `NavigationFrame`，不包含 ROS、串口或
RealSense 分支。

## 数据链路

```text
L515 对齐深度 ─► 2D LaserScan ───────────┐
S100 反馈 ─────► 轮速里程计 TF ───────────┼─► slam_toolbox
L515 RGB + 对齐深度 ──────────────────────┘        │
                                                   ▼
                                      位姿 + 占用图 + RGB-D ─► core
```

`depthimage_to_laserscan` 把深度图中央的窄条区域压缩为扫描线，
`slam_toolbox` 结合扫描匹配与 S100 里程计生成 `map` 位姿和占用图。算法输出
仍由 Adapter 转换为 S100 的低速分段运动；每段结束后停车、读取新地图并重新规划。
SLAM 模式由 ROS 独占相机；标定和直接模式由 Python 独占相机，不会同时启动两套
RealSense 驱动。

## 代码位置

| 文件 | 职责 |
| --- | --- |
| `adapter.py` | 选择直接模式或 SLAM 数据源，并执行相对位姿 |
| `ros_slam.py` | 发布里程计/相机 TF，读取 ROS 位姿、地图和 RGB-D |
| `s100_serial.py` | S100 串口协议 |
| `motion.py` | 反馈里程计、低速执行、预检和停车确认 |
| `../realsense/l515_camera.py` | 可被不同底盘复用的对齐 RGB-D 采集 |
| `../realsense/l515_motion.py` | 读取 Motion Module，并确认标定时设备静止 |
| `../realsense/calibration/` | 底盘无关的地面、视觉运动和外参求解 |
| `calibration/` | 打开 S100 并保存该底盘的标定结果 |
| `mount_config.py` | 保存和读取标定结果 |
| `mapping.py` / `planner.py` | 非 SLAM 模式的局部地图与 A* |
| `slam/s100_l515/run.sh` | 准备 USB、启动所需 ROS 节点并运行入口 |

## 环境

L515 支持已从 [librealsense 2.55.1](https://github.com/realsenseai/librealsense/discussions/12871)
移除，因此环境固定使用 ROS 2 Humble、librealsense 2.54.1、RealSense ROS
4.54.1 和 pyrealsense2 2.54.1.5217，不要单独升级这些包。标准 WSL 内核没有
L515 Motion Module 所需的 HID Sensor Hub/IIO 支持，项目用 librealsense 的
RSUSB 用户态后端绕过内核枚举；创建环境后构建一次：

```bash
micromamba env create -f slam/s100_l515/environment.yml
micromamba activate robot-nav-slam
python -m pip install -e '.[visualization]'
hardware/realsense/build_rsusb.sh
```

如果本机已有旧版 `robot-nav-slam` 环境，用项目配置同步并清理旧包：

```bash
micromamba env update -n robot-nav-slam \
  -f slam/s100_l515/environment.yml \
  --prune
```

## WSL 连接设备

`run.sh` 会调用 `prepare_usb.ps1`，在 Windows 侧识别并转发一台 L515 和一台
S100 串口设备：

- 首次共享 USB 时会弹出 Windows UAC，由用户确认。
- 脚本优先选择 `/dev/serial/by-id/`，无法唯一判断时会停止并打印候选设备。
- 已自行完成 USB 转发时，设置 `ROBOT_NAV_SKIP_USB_PREPARE=1` 可跳过该步骤。

当 UART4 和 UART1 两个 CH9102 同时连接时，先从 `usbipd list` 找到用于控制的
UART4 当前 BUSID，再明确选择它；另一个串口会保持连接，但不会被导航占用：

```bash
# Bash
export ROBOT_NAV_S100_BUSID=3-1
# Fish
set -x ROBOT_NAV_S100_BUSID 3-1
```

`3-1` 只是示例值，重新插拔后应重新查看 BUSID。

首次使用或权限规则更新后，在 WSL 中安装项目自带的设备权限规则；该步骤会请求
一次 WSL sudo 密码，并立即刷新当前 L515 USB、RGB-D 视频节点、Motion Module
和 S100 串口的权限：

```bash
slam/s100_l515/setup_usb_permissions.sh
```

`run.sh` 会在启动 Python 前启用项目本地 RSUSB 后端、检查 L515 权限并报告
USB 链路。当前项目允许使用 USB 2；检测到 `480 Mbit/s` 时继续运行，彩色流
使用 `640×480@30`，深度流使用 `320×240@30`，对齐后的深度跟随彩色图尺寸。

排错时分别查看 Windows 和 WSL 的识别结果：

```powershell
usbipd list
```

```bash
lsusb
ls -l /dev/serial/by-id/ /dev/ttyUSB* /dev/ttyACM*
```

WSL 内的 `sudo` 不能替代 Windows UAC：UAC 负责 Windows USB 共享，udev 规则
负责 WSL 设备权限。不要用 root 运行整个导航程序。

## 标定相机安装位置

相机固定好后只需标定一次；重新粘贴或移动相机后必须重做。标定前应满足：

- 地面平整且能被镜头看到，周围有静止、纹理清楚的物体。
- 机器人四周及前方至少留出 0.5 m，并准备独立断电手段。
- 相机应固定牢靠，并让画面下半部分能看到足够地面。

执行：

```bash
micromamba activate robot-nav-slam
slam/s100_l515/run.sh \
  python -m robot_nav calibrate-s100-l515 \
  --enable-motion
```

标定分四步：Motion Module 判断静止并给出重力方向；深度地面拟合高度和俯仰；
底盘依次左转、回正、右转、回正并前进约 0.20 m；最后用 RGB-D 视觉运动与
S100 里程计求解前向、左向和 yaw。Motion Module 只能辅助姿态和静止检查，不能
单独算出平移或 yaw。

结果默认写入 `data/s100_l515/extrinsics.json`，其中同时保存少量质量指标。标定
结束时机器人会停在起点前方约 0.20 m，不会自动倒回。

## 预检与导航

标定后，导航入口会自动读取上述 JSON。第一次先让驱动轮离地执行预检；该模式
只发送停止命令：

```bash
slam/s100_l515/run.sh \
  python -m robot_nav s100-l515 \
  --slam \
  --preflight-only
```

预检通过后，可先用随机评分检查真实移动链路。它不会调用大模型，也不能识别
语义目标：

```bash
slam/s100_l515/run.sh \
  python -m robot_nav s100-l515 \
  --slam \
  --target "门口" \
  --debug-random-score \
  --enable-motion
```

完整语义搜索先用 `opencode auth login` 登录 OpenCode Go，再去掉
`--debug-random-score`。入口会自动复用本地凭据；`ROBOT_NAV_VLM_API_KEY`
仍可用于显式覆盖。有多台 L515 时增加 `--camera-serial <SERIAL>`。
Rerun 默认开启，用 `--no-rerun` 关闭；`model/interaction` 可按时间查看每次
VLM 的单张 CJK 交互卡片，其中包含完整提示词、输入图、原始回应、解析结果
和目标框。

无法执行自动标定时，可至少手测高度，并用 `--camera-height-m` 启动；
`--camera-forward-m`、`--camera-left-m`、`--camera-yaw-deg` 和
`--camera-pitch-down-deg`、`--camera-roll-deg` 可逐项覆盖标定文件。用 `--camera-calibration` 可指定
另一份 JSON。

## 参数与边界

- 扫描范围：`slam/s100_l515/depthimage_to_laserscan.yaml`。L515 视场窄，效果
  弱于 360° 激光雷达；扫描使用图像中央 20 行，相机应尽量接近水平。
- SLAM：`slam/s100_l515/slam_toolbox.yaml`。
- L515 Z16 深度单位默认按 `0.00025 m` 处理；不同设备配置可用
  `--ros-depth-unit-m` 覆盖。
- USB 2 模式使用设备实际支持的 `640×480@30` 彩色流和 `320×240@30` 深度流。
  它足以调通导航链路，但深度细节较少；结果不稳定时应改善场景纹理。
- 自动外参依赖 S100 反馈积分和静态纹理场景，是适合算法研究的初值，不是计量级
  标定。结果异常时先看 JSON 中的残差与内点数，再改善场景并重做。
- 该链路不是动态障碍安全系统。首次运动必须有人能立即断电。
- Rerun 记录算法帧和分段停车后的新帧，不显示电机控制周期内的连续视频。

不加 `--slam` 时仍使用“反馈里程计 + 本地深度累计图”，仅适合小范围排错。
