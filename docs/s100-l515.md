# S100 + L515 真机 Adapter

该 Adapter 把 WHEELTEC S100 和 RealSense L515 转换为统一的
`ChassisInterface`。推荐使用 ROS 2 SLAM 模式：核心算法仍只读取
`NavigationFrame`，不包含 ROS、串口或 RealSense 分支。

## 推荐链路

L515 是前向视场的 LiDAR 深度相机，不会直接输出机器人位姿，也不是 360°
二维激光雷达。本项目先采用容易安装和排错的 2D SLAM 链路：

```text
L515 深度 ─► PointCloud2 ─► 2D LaserScan ─┐
S100 反馈 ─► 轮速里程计 TF ────────────────┼─► slam_toolbox ─► map 位姿 + 占用图
L515 RGB + 对齐深度 ───────────────────────┘                    │
                                                               ▼
                                                       NavigationFrame ─► core
```

`pointcloud_to_laserscan` 在 `base_link` 中按高度筛选障碍点；`slam_toolbox`
融合扫描匹配和 S100 里程计，发布 `map` 坐标系中的位姿与占用图。Adapter 将它们
和 RGB-D 组合成项目内部数据。算法输出仍由 Adapter 转成 S100 的转向、直行和
最终转向；每次最多移动 0.2 m，随后停车、读取新地图并重新规划。

## 代码位置

| 文件 | 职责 |
| --- | --- |
| `adapter.py` | 在直接模式与 SLAM 模式之间选择数据源，并执行相对位姿 |
| `ros_slam.py` | 发布里程计/相机 TF，订阅 ROS 位姿、地图和 RGB-D |
| `s100_serial.py` | S100 的 11 字节命令和 24 字节反馈协议 |
| `motion.py` | 反馈里程计、预检、低速差速执行和停止确认 |
| `l515_camera.py` | 非 SLAM 模式下直接采集对齐 RGB-D |
| `mapping.py` | 非 SLAM 模式下累计局部深度占用图 |
| `planner.py` | 在已知自由栅格中执行 A* |
| `slam/s100_l515/run.sh` | 准备 USB、启动 ROS 节点并运行导航入口 |
| `slam/s100_l515/prepare_usb.ps1` | 在 Windows 侧识别、共享并连接两台 USB 设备 |
| `slam/s100_l515/*.yaml` | 点云转换与 SLAM 参数 |

## 环境

SLAM 使用独立环境，避免 ROS 依赖污染核心和 Habitat 环境：

```bash
micromamba env create -f slam/s100_l515/environment.yml
micromamba activate robot-nav-slam
python -m pip install -e '.[visualization]'
```

环境包含 ROS 2 Jazzy、`realsense2_camera`、`pointcloud_to_laserscan`、
`slam_toolbox`、串口依赖和 Rerun。项目代码以 editable 方式安装，修改源码后
不需要重新安装。

## WSL 连接设备

安装 usbipd-win 5.0 或更高版本后，正常启动不再需要手动查找 BUSID。
`run.sh` 会调用 `prepare_usb.ps1`，按设备描述识别一台 RealSense L515 和一台
`USB-Enhanced-SERIAL CH9102`：

- 尚未共享设备时，Windows 会弹出 UAC；人工确认后脚本执行 `usbipd bind`。
- 已共享设备不会再次申请管理员权限。
- 每次启动都会执行普通权限的 `usbipd attach --wsl`，因为 WSL 重启或重新插拔后
  可能需要再次连接。
- WSL 中优先使用 `/dev/serial/by-id/` 的稳定路径；只有一个普通串口时才回退到
  `/dev/ttyUSB*` 或 `/dev/ttyACM*`。

脚本发现设备缺失、同类设备不唯一或串口不唯一时会停止，并打印候选设备，避免
连接错设备。此时可用 `--serial-port` 明确指定 S100；有多台 L515 时先在
Windows 侧手动 attach 指定设备，再设置 `ROBOT_NAV_SKIP_USB_PREPARE=1` 并使用
`--camera-serial`。

需要排错时，可分别查看 Windows 和 WSL 识别结果：

```powershell
usbipd list
```

```bash
lsusb
ls -l /dev/serial/by-id/ /dev/ttyUSB* /dev/ttyACM*
```

如果已经自行完成 USB 转发，设置 `ROBOT_NAV_SKIP_USB_PREPARE=1` 可跳过 Windows
脚本。设备可见但当前用户无权访问时，应配置相应的 udev 规则或串口用户组，
不要用 root 启动整个导航程序。WSL 内的 `sudo` 不能替代 Windows UAC。

## 启动

先实测 L515 光心相对底盘原点的位置。高度向上、前向和左向为正，yaw 向左为
正，pitch-down 朝地面为正。下面的 `0.60` 只是示例，不是标定值。

第一次应让驱动轮完全离地，只做预检。预检仅向 S100 发送停止命令，并等待
SLAM 位姿、占用图和 RGB-D：

```bash
micromamba activate robot-nav-slam
slam/s100_l515/run.sh \
  python -m robot_nav s100-l515 \
  --slam \
  --camera-height-m 0.60 \
  --preflight-only
```

首次运行时请在弹出的 Windows UAC 对话框中确认。脚本会自动传入 S100 串口，
无需把可能随插拔变化的 `/dev/ttyUSB0` 写进命令。

预检通过后，可用随机方向评分调试完整移动链路。下面的命令会真实移动底盘，
但不会调用大模型，也不能识别语义目标：

```bash
slam/s100_l515/run.sh \
  python -m robot_nav s100-l515 \
  --slam \
  --camera-height-m 0.60 \
  --target "门口" \
  --debug-random-score \
  --enable-motion
```

完整语义搜索需设置 `ROBOT_NAV_VLM_API_KEY`，然后去掉
`--debug-random-score`。有多台 RealSense 时增加
`--camera-serial <SERIAL>`；启动脚本会把它同时传给 ROS 相机驱动。Rerun 默认
开启，用 `--no-rerun` 关闭。真机导航必须保留 `--enable-motion`，否则入口会
拒绝发送非零速度。退出主程序时，启动脚本会一并停止三个 ROS 进程。

## 调整位置

- 相机安装位置：命令行的 `--camera-height-m`、`--camera-forward-m`、
  `--camera-left-m`、`--camera-yaw-deg` 和 `--camera-pitch-down-deg`。
- 障碍物高度、视角和量程：`slam/s100_l515/pointcloud_to_laserscan.yaml`。
- 地图分辨率、扫描匹配和闭环参数：`slam/s100_l515/slam_toolbox.yaml`。
- L515 Z16 深度单位默认按 `0.00025 m` 处理；设备配置不同时用
  `--ros-depth-unit-m` 覆盖。

## 当前边界

- L515 水平视场较窄，扫描匹配弱于 360° 激光雷达，S100 里程计和准确的相机
  外参很重要；若实测仍不稳定，再在 Adapter 内替换为 RGB-D SLAM 后端。
- pitch-down 会参与点云到扫描的 TF，但 core 当前只表达相机的平面外参；语义
  目标定位阶段应先让相机接近水平，或之后统一扩展三维相机外参。
- 该链路输出用于算法研究，不是动态障碍安全系统。首次运动必须悬空车轮，并
  保留可立即断电的人或独立停止看门狗。
- Rerun 记录算法帧和每个分段停车后的新帧，不显示电机控制周期内的连续视频。
- 环境和接入代码已配置，但尚未用到货后的 L515 与 S100 完成真机验证。

不加 `--slam` 时仍会使用原来的“反馈里程计 + 本地深度累计图”模式，方便在
没有 ROS 时做小范围排错；它会累计漂移，不应作为推荐的长距离建图方案。
