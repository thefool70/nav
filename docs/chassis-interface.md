# 底盘接口

Adapter 将设备协议转换为统一输入输出。搜索核心不直接依赖厂商 SDK，
也不承担底层路径规划和避障。协议定义在 `src/robot_nav/interfaces/chassis.py`，
数据定义在 `types.py`，公共坐标与路径计算在 `geometry.py`。

## 输入数据

| 数据 | 契约 |
| --- | --- |
| 位姿 | `Pose2D(x_m, y_m, yaw_rad)`，位于地图坐标系，米/弧度，yaw 逆时针为正 |
| 障碍图 | `ObstacleMap`；自由为 0.0、占用为 1.0、未知为 `None`，包含分辨率、原点与 `frame_id` |
| 地图原点 | 格 `(row=0, col=0)` 中心的位姿；列沿原点局部 +x，行沿局部 +y 增长 |
| RGB | H×W×3，uint8，RGB 顺序 |
| 深度 | 对齐到 RGB，单位米，表示相机光轴方向距离；核心中的无效深度为 `None` |
| 相机参数 | RGB 内参和固定安装外参；与图像尺寸、深度对齐方式一致 |
| 时间 | `NavigationFrame.timestamp_s`，秒；明确来源时钟，同流内可计算采样时间差 |

机器人局部坐标向前为 +x、向左为 +y、向上为 +z。
`CameraExtrinsics` 的平移为前/左/上，yaw 向左为正，pitch 向下为正，
roll 从相机后方向镜头看时图像顺时针为正。二维导航假设底盘近似水平、局部地面 z=0。
不能用零外参替代缺失标定。

`NavigationFrame.pose` 必须与 `obstacle_map.frame_id` 一致，转换在 Adapter 内完成。
可选地图各有用途：

- `navigation_map`：同坐标系的完整未膨胀导航图，供目标射线与停靠使用；
  `navigation_clearance_m` 指定净空半径。缺省时使用探索障碍图，不额外膨胀。
- `visibility_map`：同坐标系的未膨胀观察图，用于视线和覆盖计算。公开范围遵循观察规则，
  不能提前暴露未观察区域；缺省时使用障碍图。小孔洞过滤还要求两图格网完全一致。

相机与位姿应说明同步方法；地图可以是独立更新的快照，但需明确这一限制。
源端 Unix 时间与本机单调时间不能直接相减。接收时间新不等于曝光时间新。
`acquisition_timings` 只用于诊断，不能当作传感器采样时间。

## 执行契约

基本接口是 `read_frame()`、`send_relative_pose()` 和 `stop()`。
`RelativePoseCommand` 使用前移、左移、逆时针旋转的米/弧度表示。
动作同步返回实际到达或明确失败，不能在厂商异步 API 接受请求后立即返回。
执行反馈之后，下一周期应读取运动后的新状态。

正式导航还要求 `KnownSpaceChassisInterface`：

```text
send_relative_pose_in_known_space(command, obstacle_map, reference_pose=...)
```

Frontier 探索、回退、恢复暂存方向、目标接近和保底返回使用该接口。
显式参考位姿是选点时的位姿，不能用发送时最新位姿重新解释同一相对命令。
完整世界目标的最终 yaw 必须保留。目标接近优先使用 `navigation_map`，
其余约束动作使用 `obstacle_map`；扫描转向与启动前移使用普通接口。
不支持约束接口时应报错，不能降级为普通运动。

执行前及运动期间按决策地图检查剩余规划路径。地图外与 `None` 格均算未知，
多个未知段长度相加，默认超过 1.5 m 才停止；不跨轮询累加已走距离，
也不换用运动中新扩展的地图放宽本次约束。公共函数按线段与格网交点计算长度：
接触格角不增加长度，沿格边时任一侧未知就计入一次。
该限制不替代底盘碰撞检测和车体净空处理。

| 反馈 | 含义 |
| --- | --- |
| 正常返回 | 已实际到达所需位置/朝向 |
| `RecoverableMotionError` | 本次目标不可达，核心可选择其他目标 |
| `MotionStalledError` | 已停止、传感器可用，可从实际位置恢复 |
| `MotionPathUnknownError` | 未知路径超限，附带被拒绝路径及长度信息 |
| `MotionBlockedError` | 持续受阻，核心按动作用途处理 |
| 普通异常 | 设备、数据、取消确认等系统错误，终止运行 |

恢复前必须停止相关动作并确认必要终态；取消失败不能继续重发或宣称已恢复。
`stop()` 和退出清理应处理残留动作。Hermes 可在稳定到达后交接下一条动作，
这不等于固件已报告终态；具体监控规则见 [Hermes](hermes.md#地图与动作行为)。

## 感知与设备的边界

Adapter 提供 RGB-D、位姿、标定和动作期间的帧回调；感知模块负责采样、检测、
语义评分和定位。回调不驱动搜索状态机，也不因后台命中而取消动作。
设备不能把模型错误解释为无目标，感知不能直接控制底盘。
算法失败后的选择见 [算法说明](algorithm.md#历史与恢复)。

## 接入新底盘前确认什么

| 向厂商确认 | 本项目需要的能力 |
| --- | --- |
| SDK、系统版本、接口文档与授权 | 导航主机能够持续读取数据、创建动作、取消动作并得到反馈 |
| SLAM 建图与定位 | 可获取地图栅格、分辨率、原点、未知值和同步坐标系位姿；明确是否支持清图和建图控制 |
| 路径规划与避障 | 能发送目标位姿并保留最终朝向，获取实际剩余规划路径以检查未知区域 |
| 执行与停止 | 区分接收、执行、到达、失败；能取消并确认终态，明确急停接口 |
| RGB-D 与标定 | 可自行接入相机，取得对齐深度、内参、固定外参，确认安装与供电 |
| 时钟与同步 | 图像、位姿、地图的时间来源、频率、同步方法和断流反馈 |
| 坐标与单位 | 各轴、角度正方向、地图格中心和单位可转换到本文契约 |

当前实现为 Habitat 与 Hermes + D435i。V550 的上述能力需按实际型号、选配和 SDK 确认，
不能仅凭“支持 SLAM”认定可直接接入。
实现 Adapter 后在 `platforms/setup.py` 接入设备准备和配置，复用现有运行与搜索流程。
接口实现和静态检查不能代替实际运动验收。
