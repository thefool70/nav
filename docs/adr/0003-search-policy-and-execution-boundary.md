# 搜索核心负责行为决策，运行层负责外部调用

搜索核心决定下一步及可恢复失败后的处理；运行层读取设备、调用感知、执行动作，
再把结果交回核心。正常推进与失败恢复放在同一个行为文件中，便于沿一条流程阅读。

三个职责入口为 `core/scan.py`、`core/exploration.py` 和 `core/target.py`。
扫描包含视角规划、采集进度与覆盖；探索包含前沿提取、历史关联、选点与分支回退；
目标处理包含场景返回、物体接近与停靠选点。其他职责需要其中的计算时直接调用，
不因存在第二个调用者就另建辅助文件。`core/navigator.py` 负责输入检查、
感知增量归并、行为分派与执行反馈。

`app.py::run_navigation_cycle` 串联取帧、感知交付、决策与执行，
`launch.py` 装配组件并管理生命周期。使用普通函数、`SearchState`、
`NavigationAction` 与 `ActionExecutionResult` 显式传递数据；日志不参与决策。
Adapter 负责真实动作监控、取消和终态确认。

一个文件集中回答一个完整算法问题，专用计算靠近行为入口；合并会让文件稍长，
但减少阅读和修改同一职责时的跳转。共用数据、空间计算和无 I/O 的阶段计时分别
保留在 `models.py`、`geometry.py`、`timing.py`；设备协议、模型队列与显示保留各自
边界。不为目录对称新增包装、调度层或兼容入口。算法策略、执行顺序和恢复规则保持不变。
