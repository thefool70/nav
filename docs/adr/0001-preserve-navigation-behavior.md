# 保持实际使用的导航行为，收缩设备支持范围

本轮架构整理保持实际使用的导航行为，优先改善主流程的可读性、模块职责和状态归属，不同时调整扫描、视觉队列、分支回退和物体接近规则。这样可以避免把结构调整与算法行为变化混在一起，使后续问题更容易定位。

目标设备范围为 Habitat 仿真和 Hermes + D435i 真机。Hermes + D435i 直连正在使用，原香橙派远程链路正在调试，其远端设备已替换为随车笔记本。过渡期间，随车笔记本只承担设备数据采集与通信转发，导航、模型推理和动作监控继续在开发机运行；链路稳定后再迁移计算。这样先隔离通信迁移问题，代价是过渡期间动作监控与取消仍依赖开发机到真机的通信链路。

最终计划是将完整项目代码与运行环境部署到随车笔记本，由其运行整套导航并直接连接设备，开发机用于开发与远程操作；外部 VLM 仍通过网络调用。这是后续部署目标，不是本轮架构整理要执行的迁移，也不要求将导航计算拆成跨机器服务。

过渡期间暂时保留开发机直连与远程转发两种连接方式，用于迁移和排错对照。两种方式共用一套 Hermes 真机实现，仅在相机采集通道和底盘通信地址上区分，共用地图处理、动作监控与导航规则。

导航命令统一为 `habitat` 和 `hermes`，Hermes 通过参数选择本地或远程相机。允许同步调整配置名称、导入路径和运行脚本，去掉 `slamtec-l515`、`orangepi` 等历史设备命名，不为被替代的命令保留兼容分支；使用文档须与新入口同步。已有标定、模型和运行记录等用户数据不属于旧代码清理范围，不因重命名删除或覆盖。

本轮已按上述范围实施：Adapter 包与 CLI 子命令统一为 `hermes`
（`adapters/hermes/`、`hermes`），旧 `slamtec_l515`、`s100_l515`、
`orangepi` 旧代码和失效占位已删除，不再提供兼容分支；`docs/hermes.md` 为当前使用文档。
设备采集与通信转发仍可放在随车笔记本上，导航与模型推理继续在开发机运行；
完整部署迁移是后续工作，本轮未执行。
