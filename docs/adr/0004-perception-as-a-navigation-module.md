# 语义感知作为独立导航模块

语义感知与搜索核心并列组织，集中承载画面采样、视觉队列、模型分析和物体定位编排，不再将这些职责整体归入外部适配。采样选择、扫描合批、分析顺序和模型组合会影响导航行为，属于算法设计；HTTP、模型进程、线程同步和快照存储在感知模块内部与这些策略分开。

搜索核心决定进入目标处理或恢复探索，感知模块依据明确请求暂停或继续，不自行修改搜索状态，也不直接控制底盘。运行层串联搜索、感知和设备能力。这保留了一次感知过程的完整阅读路径，同时避免搜索决策依赖具体模型和队列实现。

`SearchState` 只由搜索核心更新，包含搜索阶段、分支、覆盖记录、活动线索和停靠尝试。感知模块管理快照、排队与在途任务以及尚未交付的结果，向搜索核心交付采集确认、分析结果和工作进度；不接收整个搜索状态并返回修改后的状态。运行层传递这些数据，不代替核心更新搜索状态。

例如画面入队后，由搜索核心登记待分析覆盖；分析成功后转为已检查覆盖，失败后释放待分析覆盖。模块之间采用普通数据对象与函数，不引入事件总线；具体字段与交付接口尚待设计。

本轮已按此组织实施：感知集中在 `perception/`（`SemanticPerception` 承载策略与队列，
`object_localizer.py` 负责历史物体定位策略，`analyzer.py` 为模型边界协议，
`snapshot_store.py` 负责快照及定位记录读写），对外只暴露
`capture_scan_view`、`score_frontiers`、`localize_object` 等请求，
通过 `begin_cycle` 返回联合分析产生的覆盖与场景/物体线索；
`SearchState` 仍只由搜索核心更新，运行层负责传递结果，由核心归并状态。
