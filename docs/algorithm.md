# 算法说明

导航围绕两个问题展开：**没有找到目标时去哪里探索，发现线索后怎样接近并判断完成。**
机器人一边积累地图，一边分析画面，在探索与目标处理之间切换。

## 两种搜索模式

| 模式 | 例子 | 完成条件 |
| --- | --- | --- |
| 物体搜索 | 找一把椅子 | 识别并定位椅子，成功停靠在附近 |
| 场景搜索 | 找到厨房 | 先接近相关线索物体，再通过环视确认已进入厨房 |

场景搜索先确定一份本轮固定的线索清单，例如厨房中的冰箱、灶台和水槽。
常用场景使用预设，其他场景由视觉语言模型生成清单。随后复用物体搜索流程。
发现一件线索物体即可尝试接近，但不代表已经到达目标场景。

## 没找到目标时，往哪里走

### 观察周围

机器人先检查附近可见、尚未充分观察的探索边界。这里的 **Frontier（前沿）**
是已知自由空间与未知空间的交界，可以理解为“从这里还能继续探索”。

扫描围绕这些方向展开，没有待查方向时采集当前画面。
画面拍下来和分析完成是两回事；只有有效分析过的观察才计入已检查范围。

### 选择探索方向

从可达前沿中筛选有足够通行空间的候选，综合考虑：

- **边界大小**：更宽的边界优先。
- **路径距离**：更近的候选优先。
- **语义相关性**：画面越支持该方向可能通向目标，优先级越高。

模型评分尚未返回时，先按地图几何信息选择，不停在原地等评分。
后台结果只影响后续决策，不打断当前运动。

### 记住没有走的分支

每次优先探索新方向，同时记住当前节点未选的分支。
新方向耗尽后，逐级返回此前的分叉点，按保存的顺序尝试仍有效的方向。
正常回退不重复扫描和评分；返回失败时根据实际位置重新观察。

## 发现线索后，怎样接近

YOLOE 持续检测画面，视觉语言模型分析扫描图和待确认的候选。
单个模型的高置信度结果可以形成线索；中等置信度结果需要两个模型在同一画面中
识别出同类、位置重叠的目标。目标识别与探索方向评分分别判断。

得到线索后，先完成当前动作，再处理目标：

```text
识别线索 → 用对应画面的深度和拍摄位姿定位
        → 选择目标附近可达的停靠点 → 执行接近
```

定位优先使用目标掩码和检测框内的深度。深度不足时，沿拍摄时的目标视线查找地图障碍，
将其作为位置假设。定位复用历史画面，不重新检测。

接近失败时有限次更换停靠点，仍失败则处理其他线索。目标处理期间暂停普通画面分析；
需要更多线索时恢复已有画面的分析。

## 怎样判断找到目标

**物体搜索**以成功停靠为完成条件，不追加到达后的重新识别。

**场景搜索**在停靠后原地环视，把各方向画面合在一起交给视觉语言模型判断。
只有确认机器人已进入目标场景才完成，判断不确定时不能宣布成功。

例如，机器人沿着冰箱线索接近后，环视发现自己仍在走廊，就继续搜索。
明确否决时，只排除本次看到且能够定位的具体线索物体，不排除所有同类物体或整个区域。

## 历史与恢复

| 遇到的问题 | 如何处理 |
| --- | --- |
| 一条线索无法定位 | 尝试下一条历史线索 |
| 所有历史线索都无法定位 | 返回首条线索的拍摄位置后停止，记为未完成 |
| 已定位，但无法接近 | 尝试其他停靠点或线索；线索用尽后可继续探索 |
| 某个探索目标不可达 | 放弃本次目标，选择其他方向 |
| 探索路径经过过多未知区域，或持续受阻 | 停止动作，在本轮搜索中屏蔽对应前沿区域 |
| 返回分叉点失败 | 从实际位置重新观察，保留其他可探索分支 |
| 设备或停止确认发生错误 | 结束运行，不继续发送运动命令 |

没有可探索方向但仍有待分析画面时，先停止运动并等待结果。
探索耗尽、达到运行上限或保底返回，都不表示找到目标。模型请求失败也不能当作“画面中没有目标”。
