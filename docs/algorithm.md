# 算法说明

算法入口是 `core/navigator.py::navigate()`。它是一个纯状态机：只根据当前
`NavigationFrame`、`SearchState` 和可选感知结果计算下一状态与一条
`RelativePoseCommand`，不直接读取设备、请求模型或执行运动。

## 一个导航周期

`app.py::run_navigation_cycle()` 按固定顺序执行：

```text
读取 NavigationFrame
        ↓
调用 navigate()
        ↓
按返回状态补充所需感知
  ├─ 单帧目标观测
  ├─ 整轮场景判断
  ├─ 目标最终确认
  └─ Frontier 批量评分
        ↓
再次调用 navigate()
        ↓
记录本周期结果
        ↓
同步执行 RelativePoseCommand
```

跨周期信息全部显式保存在 `SearchState`。`__main__.py` 只负责选择 Adapter、
构造观察器并重复调用这个周期。

## 两种搜索模式

### 物体搜索

```text
SCANNING
  ├─ 看见候选 ─► LOCALIZING_TARGET ─► 接近后重新检测
  │                                      │
  │                              距离足够近
  │                                      ▼
  │                              VERIFYING_TARGET
  │                               ├─ VLM 确认 ─► COMPLETE
  │                               └─ VLM 否决 ─► 屏蔽该位置并继续扫描
  │
  └─ 本轮未发现 ─► EXPLORING ─► 选择 Frontier 并移动
                                        │
                          无 Frontier ──┴─► BACKTRACKING
```

Hermes 物体模式使用 YOLO-World 检测候选框，再用 SAM2 生成目标掩码；检测线程
在扫描、运动和 VLM 等待期间持续处理最新帧。其他 Adapter 使用通用 VLM 单帧
观察器。

### 场景搜索

```text
SCANNING
    ↓
拼接本轮全部 RGB
    ↓
VERIFYING_SCENE
  ├─ matched ─────► COMPLETE
  └─ not_matched ─► 选择 Frontier 并移动 ─► SCANNING
```

场景模式不寻找具体目标框。每轮扫描结束后，VLM 先判断机器人是否已经位于目标
场景；只有结果为 `not_matched` 时才继续 Frontier 探索。

## 扫描

- 程序开始时执行 8 次 45° 转向，最后回到起始朝向，形成一轮完整环扫。
- 以后到达新位置时，先提取当前 Frontier 聚类代表点，再根据相机内参和安装
  yaw 计算覆盖这些代表点所需的最少视角。
- 一轮扫描开始后，视角序列保持不变；地图更新只影响下一轮候选。
- 场景模式即使没有 Frontier，也会保留当前朝向的一张图用于到达判断。

Hermes 在首次扫描之前额外规划前移 1 m。这属于真机入口的启动动作，不属于
环境无关的核心状态机。

## Frontier 生成与选择

内部占用图只有三种语义：`<= 0.5` 为自由，`> 0.5` 为占用，`None` 为未知。
Frontier 按以下步骤产生：

1. 从机器人最近的自由格开始做四邻接 BFS，得到当前可达自由区。
2. 在可达区中找八邻域接触未知格的自由格。
3. 用八邻接把这些格子聚成连通段。
4. 丢弃包围框对角跨度小于 0.50 m 的小聚类，以及路径距离小于 0.35 m 的候选。
5. 每个聚类只保留一个移动点：优先选择 0.75 m 搜索范围内离占据格最远的
   Frontier 格，再比较与聚类中心和机器人的距离。

有多个候选时，VLM 一次性返回全部候选的 `0..1` 语义分数。最终排序为：

```text
总分 = Frontier 跨度
     - 0.05 × BFS 路径距离
     + 1.5 × (2 × VLM 分数 - 1)
```

因此 VLM 对排序的影响大于一般的路径距离差，但不能让不可达格成为候选。模型
请求失败时退回纯几何排序。只有一个候选时跳过 Frontier 评分；场景模式仍会先
完成当前位置的场景判断。

## 目标接近

物体候选的位置由目标框或 SAM2 掩码、对齐深度、相机内外参与底盘位姿共同
计算：

- 深度存在时，只使用目标区域内的有效深度。
- 目标区域完全没有有效深度时，暂按 5 m 上界估计位置并接近；这只是探索假设。
- 单次命令直接走到距估计目标约 0.75 m 的位置，不限制为固定 1 m 步长。
- 估计距离不大于 0.90 m 时，不再移动，转由 VLM 最终确认。
- VLM 否决后，候选世界位置附近 0.75 m 内的重复检测会被忽略。

每次接近动作完成或可恢复失败后都会重新读取图像和深度，不沿用旧位置连续
下发命令。

## 历史与恢复

选择 Frontier 时，算法把当前位置保存为观测节点，并记录本轮全部方向：

- `PENDING`：尚未探索。
- `COMMITTED`：正在前往。
- `EXPLORED`：已经完成探索。
- `INVALIDATED`：规划失败，或该点已不在当前 BFS 可达自由区。

当前位置没有候选时，算法回到最近仍有 `PENDING` 方向的节点。所有历史方向都
耗尽后才进入 `FAILED`。

运动异常分为三类：

| 结果 | Frontier / 回退动作 | 目标接近动作 |
| --- | --- | --- |
| 规划或执行可恢复失败 | 当前方向标为 `INVALIDATED`，继续其他候选 | 保留实际位置并重新观测目标 |
| 连续静止达到门槛 | 把当前位置视为本次终点，开始新一轮扫描 | 保留实际位置并重新观测目标 |
| 持续检测发现目标并中断 | 当前方向恢复为 `PENDING`，下一帧处理目标 | 目标接近动作不会被同一候选反复中断 |

设备离线、地图读取失败和底盘健康异常不属于可恢复算法结果，仍会停止程序。

## 何时调用 VLM

| 场景 | VLM 输入 | 输出 |
| --- | --- | --- |
| 通用物体扫描 | 当前 RGB 与目标描述 | `visible` / `not_visible`，可见时附目标框 |
| 场景扫描完成 | 无标记的多视角 RGB 拼图 | `matched` / `not_matched` |
| 多个 Frontier | 带候选编号的扫描 RGB 拼图 | 每个候选的 `0..1` 分数 |
| 物体已接近 | 标出本地候选的完整 RGB | `confirmed` / `rejected` |

`uncertain` 只用于请求、解析或本地推理失败。状态机此时不发送运动命令，并在
下一周期重试，不会把不确定结果当作目标不存在。

## 排错入口

- 终端输出的 `phase` 表示大阶段，`stage` 表示当前具体步骤。
- `--debug-frontier` 在下发移动前打印候选坐标、跨度、路径距离、VLM 分数和
  总分。
- Rerun 用于对照算法候选、实际命令、Adapter 目标、规划路径和机器人轨迹。
- Hermes 每次正式导航还会写入 `data/run_logs/` 下的 JSONL 日志。

所有距离使用米，角度使用弧度且逆时针为正。完整数据契约见
[底盘接口标准](chassis-interface.md)。
