# 算法说明

算法入口是 `core/navigator.py::navigate()`。它是一个纯状态机：只根据当前
`NavigationFrame`、`SearchState` 和可选感知结果计算下一状态与一条
`RelativePoseCommand`，不直接读取设备、请求模型或执行运动。

## 一个导航周期

`app.py::run_navigation_cycle()` 按固定顺序执行：

```text
读取 NavigationFrame
        ↓
接收已完成的后台检测、评分与旧画面线索
        ↓
调用 navigate()
        ↓
按返回状态补充所需感知
  ├─ 扫描画面冻结，整轮收齐后入 FIFO（后台联合检测与评分）
  ├─ Hermes 本地目标检测
  ├─ 查询有效评分缓存
  └─ 本地物体接近后的重新观测／最终确认
        ↓
再次调用 navigate()
        ↓
记录本周期结果
        ↓
同步执行 RelativePoseCommand
```

核心跨周期状态显式保存在 `SearchState`。`__main__.py` 只负责选择 Adapter、
构造观察器并重复调用这个周期。命令行使用 `QueuedSemanticObserver`，网络与
快照文件由感知侧管理；核心只接收结果与待处理数量。直接传入普通同步观察器的
API 调用仍保留原同步语义。

## 两种搜索模式

### 物体搜索

```text
SCANNING
  ├─ 本地看见候选 ─► LOCALIZING_TARGET ─► 接近后重新检测
  │                                      │
  │                              距离足够近
  │                                      ▼
  │                              VERIFYING_TARGET
  │                               ├─ VLM 确认 ─► COMPLETE
  │                               └─ VLM 否决 ─► 屏蔽该位置并继续扫描
  │
  └─ 本轮未发现 ─► EXPLORING
                    ├─ 有新 Frontier ─► 移动 ─► SCANNING
                    ├─ 无新 Frontier ─► BACKTRACKING ─► 逐个返回，遇有效方向继续探索
                    └─ 分支退完 ─► WAITING_FOR_SEMANTICS ─► 处理线索或结束
```

Hermes 物体模式保留上述本地接近流程，使用 YOLO-World 检测候选框、SAM2 生成
目标掩码，接近后的最终确认使用当前画面。后台联合检测走另一条路径：检测到
目标后返回该画面的拍摄位置和朝向，到位即完成，不再重新定位或接近该物体。

### 场景搜索

```text
SCANNING
    ↓
整轮画面收齐后入队：检查目标场景 + Frontier 评分
    ↓
几何分与已有语义分选点 ─► 移动 ─► SCANNING

后台检测到目标 ─► REVISITING_TARGET ─► 返回拍摄位置并对齐朝向
                                      ├─ 到位 ─► COMPLETE
                                      └─ 返回失败 ─► 下一条线索；耗尽后继续探索
```

场景模式不寻找具体目标框。普通探索不等待场景结果才移动；后台列出检测匹配的
画面，按列表顺序保存拍摄位姿作为返回目标。机器人仍需实际返回该位置和朝向，
位置误差不超过 0.25 m、朝向误差不超过 5° 即完成；不再请求新图复查。

## 扫描

- 程序开始时执行 8 次 45° 转向，最后回到起始朝向，形成一轮完整环扫。
- 以后每次 Frontier 探索移动结束，`observation_coverage.py` 从当前有效 Frontier 中取出距
  相机大于 0.10 m、至多 4 m 且地图视线无遮挡的边界格，补查其中尚未检查的点。
  新候选与暂存候选都可提供观察方向；使用区域内全部边界格，避免只看代表点。
  不因普通已知区域缺少视觉覆盖而追加扫描，也不扫描隔墙或远处的 Frontier。
- 每张已检查图像记录实际覆盖的世界采样点：点须落在相机视野内、地图视线未被
  遮挡，并在相机高度及上下 0.25 m 的深度投影中得到支持；视场边缘留 5° 余量。
- 相同区域可跨位置复用。对该点的观察角度改变超过 30°，或明显接近后，仍会
  补查；新露出的 Frontier 没有旧覆盖记录，也会进入扫描计划。无对齐深度时不推测
  跨位置覆盖，只在相距 0.10 m 内复用已检查过的方向。
- 原地复用还要求对应点存在于当时地图可见的相机视锥中；新露出的区域不会仅因
  朝向相同而被跳过。转向次数和覆盖记录分别统计，遮挡后方不会被登记为跨位置覆盖。
- 根据相机内参和安装 yaw 合并同一视场能覆盖的方向；角度按 2° 分桶并预留
  对应余量，避免逐个边界格规划造成过大开销。
- 一轮扫描开始后，Frontier 观察点与视角序列保持不变；即使转向期间边界消失，
  也完成已计划的观察。下一轮重新提取和过滤 Frontier。
- 后续没有局部待查 Frontier 时，物体模式跳过扫描，直接选择移动目标或逐级
  回退；分支退完且没有有效目标才结束。场景模式仍采集当前画面确认所在场景，不为此额外转向。
- `PENDING` 表示图像已采集，等待本轮收齐或后台分析，不表示没有目标。成功的本地检测或
  后台目标判断才把对应视角加入 `observed_views`；失败不记为已检查。
- 已入队视角单独保存在 `pending_observation_views`，仅用于避免同一覆盖被重复
  拍摄，不计入已检查数量；收到失败结果后移除其待处理覆盖。这里的“已检查”
  只表示图像已处理，不保证模型不会漏检。

扫描视场须包含本轮待查 Frontier，但镜头中心不必对准代表点：同一视场覆盖多个
边界点时，中心可以落在它们之间。Frontier 的新旧选择顺序只决定移动目标，不
影响这些有效边界是否需要检查。

覆盖记录额外保留 0.25 m 固定世界网格采样和可见首层未知格，用于复用已检查
图像；它们不产生扫描需求。本轮 Frontier 格心也显式加入记录，避免因不在固定
采样网格上而反复检查。

选定 Frontier 后，核心直接把最终位置交给 Adapter；`send_relative_pose()` 同步
等待动作结束，再读取新帧、扫描和重新选点。核心不再每 2 m 插入停靠和重新评分。
执行异常或持续检测发现目标时，按恢复规则提前结束本次动作。

覆盖是相机高度附近的二维近似，不是完整三维语义地图。它不保证模型识别成功，
也不处理动态物体变化。移动中只选取有有效新 Frontier 方向的部分画面进入队列，
不会逐帧请求 VLM；沿途短暂可见目标仍可能漏检。

Hermes 在首次扫描之前额外规划前移 1 m。这属于真机入口的启动动作；若可恢复
失败或停滞且动作已结束，从实际位置开始搜索。扫描转向失败也重新规划剩余观察。

## 整轮扫描与异步 FIFO

每个普通任务保存固定 RGB、拍摄位姿、视角覆盖和候选目标快照。正常扫描收齐
本轮所有方向后只提交一批，即使途中发现新 Frontier 也不拆批；没有 Frontier 的
画面同样参与目标检测。首次环扫通常为 8 图，后续补查按实际计划的方向数合批。
扫描被目标处理打断或因转向失败重建计划时，已采集的部分画面仍合为一批提交，
不丢弃，也不混入新的扫描轮次。

拼图保留全部输入画面，V 编号采用蓝底白字的平滑笔画，放在
28 像素页眉；粉色 F 编号留在页脚，经细引线连接图内的小锚点。RGB 单图宽度
上限仍为 320 像素。页脚按实际标签分配 0–3 行，每行 30 像素；每排拼图按该排
最高页脚对齐，图间距为 2 像素，不再固定预留大块空白。

锚点在采集时计算：把 Frontier 代表点视为机器人脚下局部地面上的点，用完整
相机平移、yaw、pitch、roll 和内参投影，再核对对齐深度。点必须落在图内，
中心深度有效，3×3 邻域至少三点有效且无更近的明显遮挡；中心及邻域中位深度
与预测光轴深度的误差不超过 0.15 m。没有可靠投影就尝试其他已拍摄视角，仍无
可用锚点的候选使用几何分。局部平面是假设，坡面、台阶或标定误差可能使锚点被过滤。
移动采样仍按可见 Frontier 方位触发；地面锚点被过滤时，选中的画面仍进入目标检测。

投影像素、完整相机外参及深度核对值随图片冻结到任务快照，后台绘图不重新读取
位姿或深度。页脚最多使用三行不重叠标签，容量不足时改用其他可用视角；无法
安放的候选不请求本批评分，画面仍保留用于目标检测。

运动提前采样只在探索、返回父节点和恢复暂存方向的平移动作中启用；扫描转向、
返回线索位置、线索朝向对齐和物体接近不额外产生运动单图任务。本地持续检测
使用独立开关，扫描转向时仍可检测并中断动作。动作结束或异常退出都会关闭预采样。

移动帧先交给独立采样线程；它可以覆盖尚未选取的原始帧，已经入队的任务不会被
覆盖或因 Frontier 失效删除。当前选帧间隔为至少移动 0.75 m 或改变朝向 30°，
跳过角速度大于 25°/s 的画面。新视角可继续检测目标，同一候选目标不重复请求
已有或在途评分；失败的评分允许后续新画面补评。

普通分析由一个后台工作线程按 FIFO 处理。图片与元数据保存在
`data/run_logs/semantic-*/job-*`，队列持有文件引用，覆盖元数据保留用于去重。
检测和评分分别解析：评分格式损坏不能丢掉有效目标线索，检测失败也不丢弃有效分数。
本地物体接近后的最终确认可以直接请求模型，不排在普通 FIFO 队尾。
开始处理目标线索后，普通分析与采样线程暂停，不接受新的运动采样帧；返回与
对齐完成后直接结束搜索。已经开始的普通请求或采样可以完成，快照与结果保留，
但迟到结果暂不转成导航线索或评分，不改变当前返回目标。
已知线索之间保持暂停；全部无法返回、重新进入普通搜索后才恢复 FIFO，任务顺序
不变。本地物体定位、最终确认期间也暂停普通后台工作；任务完成后保持暂停并退出。
队列目前没有磁盘限额。正式扫描的快照写入失败会停止运行，运动预采样失败则
跳过该次采样；模型判断失败单独计数，不能把这些画面记为已检查。

分数仅匹配同一地图坐标系、区域编号和世界目标（坐标保留到微米用于消除浮点
噪声）；目标变化时不迁移分数。真正选点仍使用最新地图过滤候选并计算几何分，
已失效、不可达或屏蔽区域不会恢复。迟到评分在下一次决策使用，不中断当前移动。

目标线索按拍摄位置与朝向去重，批次按 FIFO、批内按模型给出的证据强弱顺序处理。
返回动作使用已知区路径检查；坐标系不匹配、返回或转向失败时结束当前线索，
下一周期取下一条，不在两条线索之间插入 Frontier 探索动作。
任一条返回到位即结束搜索；所有线索均无法返回才恢复原搜索分支。返回过程不再
请求目标检测、框定位或视觉确认，也不允许本地检测中断已选定的返回动作。

## Frontier 生成与选择

内部占用图只有三种语义：`<= 0.5` 为自由，`> 0.5` 为占用，`None` 为未知。
Frontier 按以下步骤产生：

1. 从机器人最近的自由格开始做四邻接 BFS，得到当前可达自由区。
2. 在可达区中找八邻域接触未知格的自由格。
3. 用八邻接形成完整的连续边界。未知侧朝向相差不超过 45°、自由区连接路径
   不超过 0.30 m 的断段可以合并，不穿过障碍，也不限制合并后的总跨度。
4. 过滤跨度小于 0.50 m 的聚类。其余区域保留全部边界格，不按长度或跨度拆分。
5. 每个区域内先排除路径距离不足 0.35 m，以及已尝试位置附近的目标格，再选
   一个代表点。代表点优先远离 0.75 m 搜索半径内的占据格，再比较中心和路径距离。
   扫描方向仍由该区域全部局部可见的待查边界点生成，不只观察代表点。
6. 根据世界坐标边界重叠关联 `region:N`，允许自由区内一个格子的边界移动。
   地图更新导致区域分裂或合并时，优先继承重叠最多的区域 ID，其余分配新 ID。子区域
   继承暂存顺序；合并时保留重叠旧区域中最先应恢复的顺序。已消失的区域退出候选。

关联有效候选前，先按完整世界边界过滤因实际路径未知长度超限而被屏蔽的区域。
屏蔽不依赖代表点或区域编号；拆分后的重叠子区域、合并后的连通区域也继承屏蔽，
已匹配边界持续保留以处理一格移动和短暂消失。屏蔽在本次运行中持续有效，不随
地图更新自动解除，也不重试被屏蔽区域；重新启动导航时建立新的搜索状态。

选择分为两层：优先探索尚未暂存的新候选，包含沿已选方向继续显露的有效边界。
选中一个后，其余新方向按本轮排名暂存。只要还有新候选，暂存方向就不参与竞争；
新候选耗尽后，沿当前分支逐个返回父节点；每到一个节点，检查它是否仍有有效
暂存方向。有则按当时排名恢复，不重新评分；没有则再退一层，不跨过中间节点。
分支顺序独立于扫描结束时的车头朝向，两种搜索模式共用这段回退流程。

后台批量返回可投影到固定图像中的候选的 `0..1` 语义分数。选择多个新候选时
查询有效缓存；未返回、失败或失效的分数使用几何分回退。未拍摄方向不标在图片
边缘，也不为评分追加扫描。新候选之间的排序为：

```text
总分 = Frontier 跨度
     - 0.05 × BFS 路径距离
     + 1.5 × (2 × VLM 分数 - 1)
```

因此 VLM 对排序的影响大于一般的路径距离差，但不能让不可达格成为候选。模型
请求失败时退回几何排序。暂存方向仍沿用原保存顺序；已经执行的移动不因普通
评分返回而改道。返回父节点不额外环扫，恢复方向后的探索停靠继续按上述规则检查。
优先级由新旧分层保证，
尚未建立房间／走廊级拓扑。

## 目标接近

物体候选的位置由目标框或 SAM2 掩码、对齐深度、相机内外参与底盘位姿共同
计算：

- 深度存在时，只使用目标区域内的有效深度。
- 目标区域完全没有有效深度时，暂按 5 m 上界估计位置并接近；这只是探索假设。
- 单次命令直接走到距估计目标约 0.75 m 的位置，不限制为固定 1 m 步长。
- 估计距离不大于 0.90 m 时，不再移动，转由 VLM 最终确认。
- VLM 否决后，候选世界位置附近 0.75 m 内的重复检测会被忽略。

每次接近动作完成或可恢复失败后都会重新读取图像和深度，不沿用旧位置连续
下发命令。

## 历史与恢复

`SearchState.frontier_regions` 维护当前可达且仍接触未知区的区域，以及旧方向的
暂存顺序。每次更新地图后重新关联边界和代表点，已消失、不可达或没有有效目标格
的暂存区域退出候选。暂存顺序中的节点序号指向 `observation_history`，该节点
记录当时出发的位置，是这组未选方向的父节点。`branch_node_ids` 另外保存
当前分支从根到叶的节点栈；已退完或本次返回失败的节点移出栈，完整历史仍保留。

新候选耗尽时进入 `BACKTRACKING`：每次 `backtrack.return` 只返回栈顶节点，
即使它目前没有暂存方向，也先实际返回。同步动作结束后，实际位置距节点不超过
0.25 m，才刷新候选；有有效暂存方向时，用 `backtrack.resume` 恢复排名最前的
方向，没有则退栈并继续返回上一节点。到达时若显露新候选，也可从该位置继续探索。
已经处于节点容差内时直接检查，不重复发送原地返回命令。

例如沿 `A → B → C → D` 探索后，返回顺序为 `D → C → B`；若 B 仍有探索
方向，就从 B 继续找。之后回退沿新的分支进行，不会因为完整历史还记录着 C、D
而再走回已退完的分支。候选使用最新地图的代表点，已消失或已屏蔽区域不会恢复。

返回动作不创建探索历史，也不消耗暂存方向；每次真正前往 Frontier 时，
`observation_history` 才记录实际尝试的移动：

- `COMMITTED`：本次命令待执行／等待下一轮扫描结束。
- `EXPLORED`：本次停靠动作已完成，不表示整个区域已经探索完。
- `INVALIDATED`：本次执行失败，不等同于地图拓扑不可达。
- `STALLED`：动作因停滞结束，保留实际位置继续检查。
- `PENDING`：动作被目标检测中断，不屏蔽该目标；对应有效区域重新暂存。

已完成、失败或停滞的目标点，按 `max(0.4 m, 2 格)` 半径屏蔽再次选点。普通失败
只排除目标附近位置；Hermes 路径中的累计未知长度超过允许上限时，额外在
`SearchState.blocked_frontier_regions` 保存整个区域边界，区域内其他点在本次运行中
也不再重试。被拒绝路径仅用于取消日志，屏蔽记录不因候选退出而丢失。

Hermes 对“当前位置＋当前剩余路径”按决策地图测量未知部分的实际长度，`None`
格和地图外均计入。多段未知部分相加，默认超过 1.5 m 才取消；不超过上限可继续，
参数为 `--max-unknown-path-m`。每次轮询重新计算，不跨轮询或动作累计行程；
只接触格角不计长度，沿格边且一侧未知时计入一次。碰撞和车体净空由底盘处理。

本次局部扫描完成或覆盖可复用后，若没有有效方向，仍沿当前分支逐级返回检查。
分支栈退完且没有有效目标时，若仍有待处理任务或线索，进入
`WAITING_FOR_SEMANTICS` 并停止移动。队列结果全部接收、线索全部处理后才进入
`explore.exhausted`；失败批次数单独报告，不宣称所有图像都检测成功。
纯等待不消耗 `--max-cycles` 的决策额度；用户中断、决策上限或设备故障仍可结束运行。
尚未消费的任务快照保留在磁盘，当前不自动恢复上次运行的队列。

运动异常按以下情况处理：

| 结果 | Frontier 探索动作 | 目标接近动作 |
| --- | --- | --- |
| 规划或执行可恢复失败 | 当前尝试标为 `INVALIDATED`，检查当前位置后重新选点 | 保留实际位置并重新观测目标 |
| Hermes 路径中的累计未知长度超过上限（默认 1.5 m） | 取消并确认动作结束，尝试标为 `INVALIDATED`，本次运行中屏蔽整个连通区域，不再重试 | 不启用此 Frontier 路径约束 |
| 连续静止达到门槛 | 标为 `STALLED`，检查实际位置并避开本次停滞目标 | 保留实际位置并重新观测目标 |
| 持续检测发现目标并中断 | 当前方向恢复为 `PENDING`，下一帧处理目标 | 目标接近动作不会被同一候选反复中断 |

设备离线、地图读取失败和底盘健康异常不属于可恢复算法结果，仍会停止程序。

以上 Frontier 恢复规则同时适用于 `explore.select` 和 `backtrack.resume`。
`backtrack.return` 也使用 Hermes 的已知区路径检查，但其失败不代表尚未尝试的
Frontier 不可达。返回动作确认结束后，若规划失败、停滞、路径未知长度超限，或
实际位置仍超出 0.25 m 容差，返回 `motion.backtrack_recovered`：保留实际位置，
将失败节点移出回退栈，下一周期重新检查当前位置。该节点的暂存区域解除暂存，
按当前地图重新参与选点；不据此屏蔽整片区域，也不将其当作已经到达。
其他节点继续保留原有回退顺序，避免反复下发同一个失败返回目标。
返回途中检测到目标则保留节点与暂存队列，先处理目标。

Hermes 的 Frontier 与回退命令使用决策帧位姿还原固定的世界目标；发送前重新
读取的位姿仅用于计算剩余距离和执行反馈。两次读取之间朝向变化不能改变目标位置。

## 何时调用 VLM

| 场景 | VLM 输入 | 输出 |
| --- | --- | --- |
| 普通扫描与提前采样 | 固定画面、V 画面编号及 F 候选方向 | 同时返回有序目标检测列表和候选分数 |
| 同步 API 物体观测／接近后重新观测 | 当前 RGB | 当前目标可见性与框 |
| 同步 API 场景判断 | 本轮扫描拼图 | 当前场景是否匹配 |
| 本地检测物体已接近 | 标出本地候选的完整 RGB | `confirmed` / `rejected` |

后台目标返回不再调用 VLM。后台分析失败不阻塞仍有有效方向的几何探索，也不把
图像记为已检查。同步观测或本地物体最终确认的 `uncertain` 仍保持当前位置等待重试。

实际提示词为英文，普通联合请求要求检查所有 V 画面，包含没有 F 标记的图片；
场景模式判断拍摄位置是否已进入目的场景，物体模式要求画面中存在目标的直接
视觉证据。输出 `target.view_ids` 中所有检测匹配的 V 整数编号，按证据由强到弱
排序且不重复；未检测到目标时为 `[]`。例如 `[3, 1]` 表示先返回 V3 的拍摄
位姿，到位即结束；仅在无法返回时尝试 V1。联合请求同时返回每个 F 方向的
`0..1` 分数；没有 F 候选时仍检查目标并返回空评分。远处门口、标牌或关联物体
不能单独作为已经进入目的场景的依据。该次联合检测就是目标判断结果，到场后
只核对位置和朝向，不再用新图推翻或重复确认它。
每次请求只发送本批图像和提示词，不附带历史对话。
Rerun 中的位姿、任务编号和区域映射是本地关联信息，不额外发送给模型。

目标判断与方向评分彼此独立：尚未看到目标不是方向的反向证据。无足够语义线索
时使用中性分 0.5；有支持证据才提高，有反向证据才降低，不强制拉开差距，也不
将各分数归一化为总和 1。模型不重复评分路径距离、代价或可达性。例如站在
洗手间门外看到标牌时，到达判断仍为 false，但相应探索方向可以得高分。

## 排错入口

- 终端输出的 `phase` 表示大阶段，`stage` 表示当前具体步骤。
- `--debug-frontier` 在下发移动前打印候选坐标、跨度、路径距离、VLM 分数和
  总分，以及新旧方向数量、选择来源和暂存顺序；返回时打印节点、返回目标、分支
  深度与该节点暂存方向数。
- Rerun 用于对照算法候选、实际命令、Adapter 目标、规划路径和机器人轨迹。
  前往 Frontier 时黄色点与橙色命令指向同一个最终位置；`backtrack.return` 的
  橙色命令指向当前返回节点，`Live` 显示节点、分支深度与该节点暂存方向数。
  World 隐藏浮动标签，稳定区域 ID
  与暂存顺序在侧栏 `Frontiers` 表格查看，实时位姿在 `Live` 查看。
- 状态面板区分局部 Frontier 点、待检查点和复用点；`scan basis` 区分首次环扫、
  Frontier 补查与当前位置场景确认。JSONL 记录实际相机位置、覆盖点数与时间戳。
  Rerun 的 `navigation/status_text` 同时保留可查询的状态文本。
- 探索动作的失败或停滞原因保留在移动历史中，下一周期可在 Rerun 状态面板查看。
- `Frontiers` 面板列出因未知路径被屏蔽的区域；JSONL 的 `rejection_scope=region`
  与 `blocked_frontier_regions` 可区分整片屏蔽和普通目标点失败。
- 返回恢复日志记录 `issue_kind`、`skipped_backtrack_node_id` 与释放的 Frontier；
  位置超差时还记录实际位置、父节点位置、距离和到达容差。
- Hermes 每次正式导航还会写入 `data/run_logs/` 下的 JSONL 日志。

所有距离使用米，角度使用弧度且逆时针为正。完整数据契约见
[底盘接口标准](chassis-interface.md)。
